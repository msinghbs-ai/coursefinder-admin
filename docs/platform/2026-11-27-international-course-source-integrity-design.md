# International Course Source Integrity — countrywide validation and autonomous recovery

**Design and delivery plan | 27 November 2026 | v1.0**
**Authority:** Platform Admin direction: all international course links and the evidence used for entry, fees and intakes must represent the actual international offering; learn provider-specific website behaviour and retain it for automatic reuse.
**Status:** Design proposed for governed implementation. No live validation, provider rule qualification, paid scraping, consumer release or data correction is implied by this document.
**Owner:** S1-Build (integration and release); Atlas coordinates Portal acceptance; S1-Data-Gaps owns link/campus/source recovery; S1-RM-Design completeness; S2-AER, S1-ELR and S1-Scholarship-Claude own their existing domains. S2-RM-Design owns DR-19. Apply [Agent Operating Model](AGENT-OPERATING-MODEL.md), [Master Plan](CONTINUOUS-DELIVERY-MASTER-PLAN.md) and the standing operational learning mandate. Do not build a second platform.

## 1. Problem and invariant

A matching course title, valid CRICOS code and successful HTTP response do not establish that the captured content is intended for international applicants. Domestic/international variants can have different fees, prerequisites, campuses, intake schedules, delivery modes and availability; a mixed page may have shared fields and audience-specific fields. A course may have an official international URL, a deep link/parameter, or a toggle that changes content without changing the URL. Page location and student qualification country are separate axes. Course availability, URL identity, audience view and field applicability must be proved independently.

**Invariant:** for every in-scope course, the student-facing link must resolve to the exact official course with an independently reproducible international view where the provider offers one; the enrichment pipeline must pass only proven applicable evidence to each reader; canonical facts and consumer presentation must preserve audience, course, scope, year and source lineage. A link label is not proof. A missing or unresolved fact stays unknown/held, never filled from domestic content. Keep legitimate domestic source evidence separately; do not overwrite or delete it.

## 4. Provider website behaviour — reusable audience recipe

A provider can have multiple templates by study level, campus or programme family. A recipe is scoped to provider stable ID, verified official domain and template/path family, not a global URL replacement. Store observed, proposed, qualified, active, stale/disabled status through existing qualification and versioned configuration; preserve old versions. Do not assume all courses on one domain behave identically.

| Pattern | Acquisition method | Student link behaviour |
|---|---|---|
| Dedicated international course page/subdomain | Discover official counterpart through provider navigation, sitemap or stored link evidence; verify exact offering and content | Persist verified international landing URL |
| Shared route with documented deep link, parameter or anchor | Replay observed navigation; fresh-session verification, preserve meaningful query parameters during normalisation | Persist independently reproducible international URL |
| Same URL, JS tab/toggle/dropdown | Use qualified bounded browser action (click/select, wait for positive state and field container), capture resulting content, compare domestic negative control | If no shareable international URL exists, retain correct shared URL with clear instruction to select International; never claim it opens directly in international mode |
| Shared page with simultaneous sections/tables | Parse visible headings, tab state, column headers and row scope; isolate international and explicitly common sections | Shared link labelled as such; do not pass mixed unlabeled evidence |
| Public official handbook/PDF/fee schedule | Match exact programme/code, year, audience and campus; preserve section/page coordinates | Link to official course page if available; evidence may be separate; do not substitute a generic PDF or regulator listing as course page |
| Geo/cookie/session preference | Reproduce in isolated sessions; verify actual rendered content, not geo setting alone | Prefer stable public shareable link; if impossible, show instruction or hold direct-link verification |
| Restricted, ambiguous, no official international page | Record exact reason; permitted alternate official source; no access-control or robots circumvention | Do not pass a domestic link as international; approved honest fallback or suppress official course action if no correct link |

Recipe contract (illustrative configuration, not actual selectors): provider_id, approved domain/path scope, template fingerprint, navigation mode, known landing/deep-link evidence, public action whitelist, state-ready predicate and timeout, positive international marker(s), negative domestic marker(s), exact identity anchors (provider course code, regulator ID where available, title/level/offering), field section selectors and audience tags, shared-section evidence rule, redirect allowlist, locale, evidence extraction/normalisation version, tested positive/negative course samples, verified time, expiry/drift condition, authority/qualification reference, cost/attempt bounds, owner and fallback. Use semantic stable selectors over positional CSS when possible. Configuration is data; no executable user-provided scripts or prompt instructions from pages. Treat links/page content as untrusted data.

## 5. Acquisition ladder and Firecrawl

1. Reuse stored immutable HTML/PDF and previous successful results if relevant audience and identity are actually provable, sufficiently fresh and matching qualified recipe/version.
2. Direct official HTTP/HTML, official public documents or supported public structured endpoints (no bypass of access controls); use known deep links or public navigation. Store original and final URL, redirect chain, capture time and content hash.
3. Use existing Firecrawl acquisition integration for dynamic content only when needed. Firecrawl documents scrape Actions (click/wait/screenshot) and stateful Interact/Playwright-style navigation: https://docs.firecrawl.dev/features/scrape . S1-Build must verify current SDK, API contract, account capability and cost before qualification. Prefer deterministic, bounded replay of a qualified provider recipe to AI-controlled browsing for every page. Verify state after click (e.g. selected international tab and appropriate fee/entry heading); a wait alone is not a proof. Store post-action HTML/markdown, selected-state evidence and optional screenshot, not just default pre-click content.
4. For unknown templates, use a small bounded discovery sample and AI-assisted proposal if authorised; inspect actual page and official alternative, prove negative/positive states, qualify recipe through existing control. No autonomous unreviewed recipe activation, arbitrary script, navigation outside approved public domains, submission of forms, personal details, logins or new paid tools. Firecrawl location/language is not equivalent to international student audience.
5. Reuse the qualified recipe across the matching provider cohort, with per-page identity and audience checks. Changed structure, missing expected markers, unexpected redirect or ambiguous variant -> stop only affected item/template, record issue, requalify or use authorised alternative. Honour rate limits, retry/backoff, evidence fingerprints, manual locks and approved caps. No new spend authority or all-catalogue paid crawl.

## 6. Processing contract (one pipeline)

Existing planner -> link candidates -> exact identity gate -> international-view resolution -> evidence capture -> audience/section preprocessing -> qualified field reader -> quote/identity/audience/field validation -> existing admission -> canonical active facts -> publication -> Portal/Website/Zoho readback -> learning.

Use the same shared selection mechanism for scheduled, Run Now, batch and qualification paths. Do not create separate selection logic in each reader. Produce typed diagnostic metadata alongside existing evidence (adapt to actual contracts): provider/course/offering IDs; candidate and resolved URL; identity proof; view mode (international, shared-explicit, domestic, ambiguous, unavailable); reproducible-direct-link status; recipe version/hash; capture/evidence ID and timestamp; content hash; selected audience and state proof; per-field chunks with path/heading/table row/column/page, exact source quote, audience/scope/campus/year/currency/basis as applicable; rejection reason and next action. Keep raw evidence immutable. A section explicitly applying to both may be reused; a section with no explicit label may be accepted only with positive contextual proof from the verified international view/official offering. Absence of a domestic marker is insufficient.

Preprocess for AER, ELR, tuition, intakes and other readers: retain hierarchy, table labels, qualifiers, full relevant clauses and official document coordinates; strip navigation, cookie banners, unrelated course cards, domestic panels and hidden inactive tabs. Don't globally discard useful shared facts; ambiguous mixed tables are held. Pass only required applicable chunks and typed context to existing AI route, not whole pages by default. Require model to return structured values plus exact evidence references; no model inference of missing values or permissions. Deterministic validators re-check quote, audience, identity, course/level/campus/year/fee basis and semantics. Preserve distinction between study destination and student's education country; a general international requirement is not country-specific equivalence or eligibility. Preserve admission policy and locked values.

## 7. Correct existing values without unsafe bulk withdrawal

Trace each previously admitted AER/ELR/fee/intake row to evidence and audience; compare source snapshot, course scope and current authoritative page. Prioritise published courses with domestic contamination suspected, missing/incorrect international links and Feedback 3–6 cases. Reuse existing DR-19 trace, manual locks and field lifecycle. Flag suspect values with evidence and correct through domain-owned existing admission/verification path; do not mass relabel domestic values as international, delete evidence or overwrite locks. Any consumer suppression/withdrawal or G3 changes require applicable authority and notification. If a verified international source cannot support a value, record exact reason and authorised lifecycle disposition rather than inventing a replacement. Do not infer annual tuition from total; do not infer intake availability from start date; do not use a domestic ATAR/HECS/CSP or local fees as international facts. An admission instruction/age/pathway is not a qualification threshold. For shared programme codes/offerings, verify exact audience and specialisation, not duplicate catalogue rows.

Student navigation: verify outbound link in clean browser/session (desktop/mobile) using the real consumer-selected URL, not crawler cookies. Prefer directly reproducible international URL. If provider stores selection in local/session state and cannot deep link, no platform can guarantee a third-party site opens in international mode for every student; show correct shared official course link with explicit instruction and distinct status; never fake the URL or silently send domestic page. If consumer API behaviour changes, apply G3 and platform-specific notice (M3/Comms).

## 8. Countrywide execution and rollout

Phase A — inventory and reconcile: use bounded incremental existing coverage/build queries to enumerate every in-scope course, selected URL and active link/evidence, provider/template grouping, actual consumer link precedence, previous attempts, audience and freshness; no paid acquisition. Report denominator, known/tagged/untagged/missing, stale/unproven, verified and exclusions separately. Prioritise stored usable evidence, current high-risk published/feedback courses and providers with largest course impact; then missing links. No whole-db recurring scan.

Phase B — qualify representative templates: start AU (feedback providers and high-coverage templates); sample positive and negative examples including international-only, dual offering with distinct URLs, mixed sections, same-URL toggle, shared no stable link, domestic-only, redirect/wrong course, expired offer, mobile/clean session, fees/year/campus and ELR/AER/intake differences. Do not invent provider-specific rules in the design; observe real pages and store rule evidence. Reuse existing source profile validation and qualification; maintain one recipe per applicable template rather than one-off course patches. Use direct/stored evidence first. Activate only within existing authorised qualification/control.

Phase C — process every AU in-scope course through existing bounded provider batches, no manual waves; course-level evidence check on every result, not sample extrapolation. Prioritise repair of confirmed wrong audience and existing eligible evidence; keep correct courses processing, park genuinely blocked records with DR-19 reasons. Record changed source/recipe and next action. Continue NZ, CA and later approved destinations with same contract and country-specific regulator/source rules. Track all courses as verified, pending or specific exception; countrywide coverage accounting does not mean every provider offers an international page.

Phase D — admission and delivery: owners correct affected fields through existing gates, verify source-to-canonical-to-Portal and Website/Zoho when applicable. Separate URL correction, audience qualification, field correction, publication and consumer readback counts. Do not reopen D9 or bypass its notice gate. No claim of new admission for a projection-only change.

Phase E — continuous self-sustainability: existing periodic freshness, link checks, planner, evidence-change checks and first-run-verify detect drift (URL/redirect, template, state marker, field section/year, source hash, course lifecycle). If eligible known remedy exists, use within authorised scope and reverify. Unchanged/no-yield evidence -> existing block and retry policy, not another paid read. Unknown template -> propose qualified rule via existing workflow and continue others. Record actual cost, outcome and recurrence; promote only after evidence. No new scheduler. Existing active jobs/capacity remain; measure latency and yield.

## 9. Existing knowledge and lesson capture

Every validated fix/failure links issue fingerprint, recipe version, scope and source/evidence hash to ops_remedy_knowledge, ops_remedy_outcomes, ops_remedy_blocks and existing policies. Examples: default domestic vs switched intl; distinct URL; country parameter not audience; mixed fee table; hidden DOM inactive panel; missing specialisation vs missing course; ambiguous same title; redirect/geo state; quote present but wrong audience; year/fee basis mismatch; no published info; refused acquisition not missing data. Reuse existing registered qualified remedies; new selectors or code changes must follow governed release and negative controls. Store failed recipe attempts and no-retry reason. Use existing evidence and outcome record rather than building a provider-specific AI memory database.

## 10. Admin and acceptance

Use existing provider/source profile details, course Field processing status/diagnosis, Data Delivery and Layer 4. Surface selected link and audience proof, recipe/version/qualification, last check and evidence, reason for hold, affected fields, recovery action/owner and verified consumer link. A tag or HTTP status never counts as verified.

- every AU in-scope course accounted for, then NZ/CA; report actual measured statuses and denominators, no extrapolation; no false claim that all links were fixed;
- each accepted direct international link resolves exact course/audience in clean browser, each shared non-deep-link has explicit honest instruction; negative controls reject domestic-only/wrong course/mixed ambiguous evidence;
- each admitted affected value has exact applicable evidence and readback; protected locks unchanged, no accidental domestic values; verify Portal with real course/roles and desktop/mobile, Website/Zoho separately under existing G3 controls;
- prove at least two unattended result-bearing cycles including one known template reused and a drift/unchanged/no-yield exception handled safely; verify no unnecessary paid rereads or duplicate work;
- preserve CI/main green, release controls, cron ceiling 140, protected data/locks and financial limits; record before/after link/field gains, publication, consumer match and actual cost; verify unaffected throughput/latency. This is workstream acceptance, not an additional launch-blocking architecture milestone.
