## Purpose

Finish the current AER chapter and return the platform to sustainable data enrichment. Stop the cycle of chat-pasted prompts, optional expansion and unverified progress claims. GitHub is the durable handoff and accountability channel between agents.

## Mandatory repository workflow

1. Read `docs/platform/AGENT-OPERATING-MODEL.md`, this folder's `INDEX.md`, the latest AER handback and live-status checkpoint before acting. Follow Pilot `CLAUDE.md` for execution.
2. Claude reads this mandate directly from GitHub. Do not wait for it to be pasted into chat.

4. Claude writes its full response to `docs/platform/nz-enrichment-brief/2026-10-30-aer-production-closure-response.md` and keeps the current AER live-status checkpoint updated. If work extends beyond the day, create dated continuation files and link both ways; do not overwrite history.
5. Before each work stage, fetch `main` and inspect relevant changed files. While an agent session is active, recheck GitHub at least every 15 minutes and after every handoff. Reconcile other agents' changes before writing; never overwrite or duplicate them.
6. Continue working until the mandate is verifiably complete or a genuine Platform Admin, human-review, spend or external-service gate stops progress. Record that gate and the exact next action in GitHub.
7. Continuous means continuous within an active runner/session. No agent may claim offline, stopped or completed sessions are still monitoring or working round the clock. A resumed session starts by reconciling GitHub and live state.
