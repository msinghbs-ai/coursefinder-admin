## Single-release safety remains mandatory
1. **One active production mutator/release at a time.** Before each release or governed write, Claude reconciles current GitHub heads, active/in-flight deploy or migration workflows, live migration ledger, settings, hashes, open production incidents and outstanding approvals. Use actual workflow concurrency and idempotency protections; do not merely assert exclusivity because this decision names a controller. If the deployed mechanism lacks a required serialisation check, add the smallest compatible guard through the normal reviewed release path. Never run competing migrations/writes.
2. **All normal PRs:** Claude diagnoses, fixes, retests, requests independent QA when appropriate, integrates and merges under the standing full-green/zero-skipped CI, production checksum, evidence and housekeeping rules. Routine technical decisions, conflict resolution, migration ordering analysis, QA amendments, safe settings and retries do **not** return to the Platform Admin.
3. **Protected actions stay protected:** Destructive data operations, new or materially changed consumer API contracts (G3), new spending beyond approved caps, manual-lock overrides, unsupported machine admission policy and actions outside authenticated permissions retain their explicit Platform Admin or external-authority requirements. A previously recorded, appropriately scoped approval need not be asked again; any required audited setting or developer communication still must actually occur.
4. **Every operation has evidence:** pre-state, approval or standing authority, PR/commit, QA, deploy job and applied migration, actual canonical result, Website/Zoho publication where relevant, rollback/forward recovery, and next automatic batch. Record in `STUDYSEARCH-EXECUTION-REGISTER.md` and existing `pipeline.integration_issues`; no parallel controller register.
5. **Interrupted work:** A new Claude session independently reconciles actual unfinished jobs, last applied migration, successful/failed writes and pending PRs before resuming. An old session or stale historical lease neither transfers authority nor proves a release complete. Continue safe independent tasks if a particular action is blocked.
6. **Delivery criterion:** a released PR or green job alone is not complete. Continue source → evidence → correct admission → actual Website/Zoho publication → verification → self-recovery, using the existing scheduler and incident queue. Only a genuine new authority, financial, destructive or external dependency is escalated, once and precisely.
