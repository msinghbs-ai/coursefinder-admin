# Decision — F-CDESC source-grounded description replacement (11 Nov 2026)

**Detailed production design:** [Controls, UI, prompt and operator guide](../COURSE-DESCRIPTION-PRODUCTION-DESIGN.md). This is a straight production implementation, not a proposed new pilot or manually enabled release trial.\n\n**Authority:** Platform Admin instruction, 11 Nov 2026. **Status:** Approved design direction; engineering release, production baseline and governed retirement NOT yet verified. **Owner:** Claude, sole Integration Controller. **Execution:** existing F-CDESC.01–.06 and F-OPS.03A, not a parallel programme.

## Why / observed failure
The CourseFinder Website sample shows generic promotional and repeated template descriptions for Diploma of UX and Web Design and Graduate Certificate in Information and Communications Technology. Displayed text stops mid-word or mid-sentence; determine whether this is canonical truncation, search projection/API truncation, or UI excerpt length before changing the producer. The Claude assessment reported about 66% verbatim copying in candidate sentences, and 2,718 blank courses held by strict length/figure/word constraints; these are **reported claims awaiting reproducible measurement**, not independently accepted production counts. Do not infer that a blank field implies no attempt.
The existing F-CDESC route already includes AI read, bounded recording, course_description_check, narrow cdesc-machine-v1 admission, Layer 4 exceptions, a settlement job, publication and consumer read-back. The 10 Nov register records lost paid answers and stranded queued work; Pilot #1001 was reportedly deployed on 11 Nov to fix recording/settlement interaction. **Do not launch an isolated second reader/queue/dashboard or turn off working controls.**

## Authorised target
Replace the ineffective GENERATION contract and obsolete redundant paths with a single source-grounded course-description route. Course descriptions must be useful, clear, original prose and distinguishable by course. Never fabricate curriculum, placements, accreditation, fees, employment outcomes, rankings, delivery or intakes. Do not rewrite source text merely to evade a plagiarism check: use source facts and genuinely fresh explanatory language. Direct quoted passages require source attribution and authorised policy. Existing licensed/official source rights and publisher terms remain applicable.

1. **Source hierarchy:** existing captured official course evidence (including hash/date, provider/course identity) → verified official direct fetch → governed Firecrawl where needed. Use official course catalogue, syllabus, units, outcomes and delivery/course structure facts only when evidenced. Reuse already paid answers where valid and never acquire the same unchanged source needlessly.
2. **Evidence record:** stable course ID/CRICOS, canonical source URL and content fingerprint, source page/version, extracted fact spans or quotes, applicable provider/campus/study level, extraction attempt, model/prompt version, cost, reason and next retry. Reuse existing source/provenance records and lineage; do not invent new tables without confirming the current schema.
3. **Prompt template:** course-specific, auditable internal prompt stored in version control with a governed internal setting or existing prompt configuration where supported. Require 2–4 complete plain-English sentences, roughly 55–100 words as a *quality objective*, not an arbitrary hard rejection rule; produce concise truthful copy when evidence is sparse. Include actual course subject and substantiated curriculum/outcomes and optional unique structure; omit unsupported assertions. Australian English; no universal boilerplate, repetitive formula, false certainty or promotional superlatives. Separate source-language overlap checks from normal course titles and proper nouns.
4. **Validators:** exact course/provider identity, each material claim source-supported, complete sentences, no mid-word truncation, acceptable similarity not copied sentences, no invented facts, manual locks and previously rejected evidence. Sentence/length/figure/word rules are reviewed as an integrated policy; don't silently lower protected thresholds, disable evidence checks or introduce another Settings wall. Classify fail reasons (missing source, incomplete fact coverage, exact copying, ambiguous identity, length only, technical, budget, genuine human hold). Keep source length and consumer excerpt limits separate.
5. **Admission:** reuse the authorised narrow cdesc-machine-v1 safe class, source quotation/proof, Layer 4 for true policy/identity ambiguities, audit actor separation and bounded settlement. New prompt output does **not** automatically expand machine-admission or publication authorisation. Check existing scope against 10 Nov decision and G3 rules. No bypass by lowering `review_first` or other settings.
6. **Throughput and replay:** worker records only bounded work; settlements/consumer parity in catalogued jobs. Replay stored paid answers before re-asking; recover terminal failed/stranded jobs and put every work item in a retryable/held/settled state. Enforce existing per-day caps, credits, AI budget, one production mutator and idempotency.
7. **Publishing:** canonical `catalogue.courses.description` → existing search projection/Website read-back; verify text and truncation in both API and rendered excerpt. Zoho currently may not expose a description field: no frozen consumer API change without G3 approval. Existing manual source-backed descriptions must not be overwritten.

## Execution order — replace and retire safely
**CD-R0 audit:** Reconcile currently deployed course generator, prompt/config, course-text Worker, SQL validation/admission, settlement, course catalogue/search projection and visible Website snippet. Classify redundant or inoperative components by file/function/settings/job, with call sites and preserved data; compare representative exact source evidence against samples before attributing truncation to the generator. Record measured counts and before-values, not screenshots as live SQL truth.

**CD-R1 repair source→record→settle:** Before new AI spend, prove #1001 deployed and two unattended working cycles. Replay orphaned paid answers; recover queue leases; resolve recording time-outs at owning boundary and measure attempted, recorded, admitted, published and failed records.

**CD-R2 replace prompt/generator:** Refactor existing `supabase/functions/coverage-sweep/course-text.ts` or actual owning generator path; version and test a source-to-original-prose prompt with factual evidence and relevant course distinctions. Reuse the existing AI provider/model and cost controls. No separate new platform reader unless a demonstrable missing source parser capability requires it.

**CD-R3 cohesive validation:** Reconcile `security.course_description_check_v1` and the active machine gate with current policy; avoid hard-stop length checks on otherwise truthful concise descriptions if a policy-authorised controlled adjustment is made. Test original/near-copy text, hallucinations, sparse-source descriptions, truncation at canonical/API/UI, unchanged source, missing source, manual lock and rejected prior reading.

**CD-R4 bounded comparison:** Reuse production-shaped **regression fixtures as release tests only**, not an additional launch pilot or a reason to postpone the already approved live admission path. Compare old vs new for factual accuracy, duplicate language, completeness, source citation, cost, rejection reasons and consumer presentation. Nothing from test evidence is automatically published. Independent QA is required at the release boundary.

**CD-R5 governed replacement:** Release the replacement through normal Pilot PR / exact-head G1–G4, migration MD5 and independent QA. Run authorised production admission and existing scheduled queues. Retire old generator branches, stale prompts, redundant retries, inert settings and any obsolete job **only after** all inbound callers, pending tasks and dependencies are checked, previous data preserved, and rollback/forward recovery documented. Destructive operations require separate Platform Admin authority. Avoid a second live job writing the same field.

**CD-R6 acceptance:** Prove actual source-backed canonical growth, accurate publication and Website read-back for distinct providers/courses, no malformed truncation, two unattended cycles near measured throughput capacity, truthful reasons for not-found/held records, retries continuing without manual babysitting, and no regression to provider fields or consumer API. Record prior→new counts, exact PR/commit/deployed function, CI/QA, source IDs, canonical IDs and consumer URLs in existing Execution Register / F-CDESC rows. Do not declare delivery from a PR, a shadow trial or an estimate.
